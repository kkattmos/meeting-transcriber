     Plan: Split meeting-transcripter into 3 composable options

     Context

     The current project is one monolithic pipeline: record_and_transcribe.sh 
     <url> <name> [display_name] [lang] joins a meeting, records audio into a
     virtual sink, and runs whisper.cpp on the WAV. It cannot:

     - Record the screen (only audio is captured).
     - Process an existing audio file (it always joins a fresh meeting).
     - Produce an AI summary that combines what was said with what was shown.

     The user wants three self-contained, composable options that can be run
     individually or chained together:

     1. Screen recording — capture the meeting browser window to MP4 (video +
     audio).
     2. Transcribe — voice-to-text, accepting a recording produced by option 1
     or any audio file.
     3. AI agent summary — feed a transcript + keyframes from the video into a
     vision-capable LLM via the FCC Claude endpoint, and produce a summary.

     The existing code (login flow, Xvfb + PulseAudio + Playwright, kill switch,
     Thai button labels, trigger server) is the foundation for option 1's
     meeting-join step. The new work is mostly additive: extract the existing
     audio-only recording path into a shared library, add a video recording
     path, add a standalone transcription entry point, and add the AI
     summarizer.
